# Comparison method

Review date: 2026-10-22. Synthex source: `7babe5ef2c2d1959e680d6edfc19bc384ce428ea`. Official shadcn source: `25af02b1b467fcd53b63e0c6d6d324c57c16ef18` (`shadcn` 4.22.1).

Five independent automated critic passes assess separate dimensions. They are not five customer interviews; use of the same model family and shared methodology can correlate judgments. Each defines a weighted rubric totaling 100%, rates both products out of 10 on that dimension, and cites source or observable evidence. The ratings express expert judgment; they are not benchmark measurements, user-study results, or proof of universal superiority. Reviewers use the same source snapshot and work without reading each other's reports.

Score anchors: 0 = task unsupported; 2 = concept or severe blockers; 4 = partial implementation; 6 = useful but material limits; 8 = coherent and well evidenced; 10 = exceptionally complete for the defined use case, with release and user evidence. Fractions reflect rubric arithmetic, not additional measurement precision. Each report must show criterion scores and weights so the total can be checked.

Merged source, npm release, automated host tests, browser evidence, Metro exports and device evidence are separate categories. Synthex 1.1.0 on npm predates this merged work; source capability must not be advertised as a verified published release. Mocked native tests and Metro exports do not establish device behavior. shadcn's web scope must not be treated as an implementation defect; cross-platform task coverage is assessed explicitly for a web-and-mobile team.

Competitor facts come from the pinned official repository or current official documentation, not this repository's older comparison. Missing evidence is stated as uncertainty; an unsuccessful search alone cannot prove a feature absent. Credit shadcn's current diff/dry-run, migration, presets, registry, MCP and assisted update workflows where applicable.

Each critic supplies: domain and rubric; both numeric scores and their breakdown; at least three concrete strengths/gaps per product; exact local paths/lines plus pinned competitor source URLs; confidence and unverified assumptions; one defensible Synthex opportunity; disconfirming evidence that would overturn it; and three bounded acceptance tests. No popularity proxy substitutes for implementation evidence, and no visual judgment is claimed without visual inspection.

The synthesis will choose a single narrow customer problem, distinguish an implemented advantage from a commercial claim, and propose a falsifiable benchmark and staged work. It will not average unlike domain ratings into an unexplained universal score.
